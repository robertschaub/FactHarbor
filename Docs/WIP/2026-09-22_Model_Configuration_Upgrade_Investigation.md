## 1. Recommendation

**Keep the deployed allocation unchanged and retain Haiku 4.5. Prioritize complete cost accounting and faithful narrative inputs, and reconcile the generic decomposition rules with Captain expectations before further paid comparison.** These existing-path corrections offer a grounded quality/value opportunity: a stronger model cannot be credited with faithfully summarizing conclusions it was never given, and incomplete costs cannot establish the 25% target. Implementation and any restarted run remain separate decisions; the conditional two-job preview below is not execution-ready. The correction addresses the confirmed consumer contradictions while preserving the intentional historical exception. The initial advocate screen prioritized medium because its 8.6% extra stage cost fit the selected envelope; quality was inconclusive. Native output remains a compatibility candidate, not a validated quality upgrade. Disabled remains a lower-cost comparison arm, but its earlier German retry decision was not stable. Neither effort setting is ready for promotion. Evaluate a newer OpenAI challenger separately after the Claude lane has a usable baseline; premium models remain escalation/review candidates.

**Phase C interpretation:** earlier tool responses returned `{}`, an unexpected `$PARAMETER_NAME` wrapper, and `{"parameters": null}`; all were rejected locally. Four native responses passed the lenient actual schema. German native medium then denied an existing literal carrier: a **material traceability violation under the frozen rubric, with a supported overall retry decision**. This justified stopping before its paired control, but does not establish that effort/transport reduced final analysis quality. Offline execution confirms different retry instructions; their benefit or harm is untested. All four adaptive-policy tool calls reported zero thinking tokens/no thinking block, unlike the two native medium calls. Consequently this route comparison cannot isolate formatting from observed thinking behavior.

This is a candidate upgrade, not a demonstrated end-to-end quality improvement. Newer models may improve evidence synthesis, qualifier preservation, and instruction adherence. They cannot recover missing evidence, undo a discarded source, or repair a claim decomposition that the replay holds fixed. FactHarbor's history repeatedly shows why these distinctions matter.

The best immediate value is **better control and measurement of the existing model allocation**, followed by one isolated model change. Do not combine a model upgrade with looser sufficiency thresholds, changed retrieval limits, prompt rewrites, or disabled debate checks. Otherwise a positive or negative result will be difficult to attribute.

At the investigation baseline, an existing configuration field could select Sonnet 5 but could not set its thinking policy; a pure model-string change used the provider defaults assessed separately in §5. Phase B now supplies explicit policy controls and rejects that incomplete candidate configuration. These controls have passed offline checks; their full-analysis effect remains unvalidated.

**The configuration-only shortcut is not the recommended first rollout:** its six additional advocate calls cost 71.8% more than the matched original baseline calls, compared with 8.6% more for explicit medium thinking. Those are stage costs, not measured whole-analysis changes. Full-report quality gains remain unproven in every arm.

### Compatibility findings verified in this checkout

1. **The installed SDK already recognizes the new Claude models.** `package-lock.json` and the installed package resolve `@ai-sdk/anthropic` **3.0.118**. Its model capability logic strips unsupported sampling parameters for Sonnet 5. An offline `generateText` request capture confirmed that FactHarbor-style `temperature: 0` becomes an omitted request field. A claimed inevitable HTTP 400 from temperature would therefore be wrong for this checkout.
2. **That is a behavior change, even when requests succeed.** Existing `selfConsistencyTemperature: 0.4`, clustering `0.05`, and other temperatures cease to govern Sonnet 5. Repeated-call stability needs re-measurement. [Sonnet migration guidance](https://platform.claude.com/docs/en/models/sonnet-5/migration-guide) also establishes that thinking now defaults on, effort defaults high, thinking consumes billed output, and tokenization changes.
3. **Explicit thinking controls are not presently wired from UCM.** The common helper in `llm.ts:50–61` returns only `structuredOutputMode: jsonTool`; the Stage-4 caller passes it at `verdict-generation-stage.ts:519–538`. Setting `modelVerdict` alone does not select medium effort or disable thinking. Those proposed settings need small code/schema/UI support, and coverage of every affected call site.
4. **Structured output is model-specific.** The offline capture showed that schema-constrained `jsonTool` requests emit `tool_choice: any`. Sonnet 5 supports forced tools with adaptive thinking; Fable 5.1 rejects forced tool selection. Fable is therefore not a safe blanket string replacement for schema-heavy stages. An actual nested FactHarbor schema still needs a live smoke test for any chosen route. [Official tool restrictions](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools).
5. **Challenger pinning has a real configuration limitation, but not an absolute impossibility.** Roles expose `{provider, strength}`, not a model ID. `LLMCallFn` declares `modelOverride`, but the production caller does not use it. A configuration-only experiment can put `gpt-5.6-terra` in `modelOpus` and set only the challenger to OpenAI/premium: the existing premium branch copies it into `modelVerdict`. This overloads a shared slot and becomes fragile if another premium role is introduced. Prefer a reviewed optional model override within the existing role object if independent pinning is retained long term; do not build another routing system.
6. **Accounting must be updated with the upgrade.** `metrics.ts:578–644` uses simple input/output prices, lacks these new IDs, and silently falls back to $2/$6. It records cache counters but does not price them separately; search is estimated uniformly at $5/1,000 queries. Its total is not adequate to enforce a 25% cost decision for new models. Preserve provider usage, including billed thinking/cache writes, and date the rate table. Count thinking once, as part of output, not twice.
7. **Record refusal and truncation outcomes explicitly.** The [Sonnet 5 migration guide](https://platform.claude.com/docs/en/models/sonnet-5/migration-guide) documents HTTP-200 responses with `stop_reason: refusal`. The installed SDK maps this to `finishReason: content-filter` and exposes `rawFinishReason`. Claim selection already handles `content-filter` explicitly (`claim-selection-recommendation.ts:291–303, 471–475`), and Pass 2 has partial detection. The common `LLMCallMetric` has no finish-reason fields, while the Stage-4 caller does not inspect them. Extend existing records/handling so a refusal is distinguishable from malformed JSON; do not claim the entire pipeline is unaware of refusals or that all refusals necessarily have empty text. None occurred in this pilot.

The authenticated Anthropic Models API listed Sonnet 5, Opus 5 and Fable 5.1 for this account. Paid successful Sonnet calls are recorded in §5; Fable/Opus report-review calls are recorded in §9. OpenAI and Google account access and rate limits were not established by that check.

The OpenAI TPM precheck and retry fallback explicitly match **`gpt-4.1`**, not all OpenAI models (`verdict-generation-stage.ts:486–495, 580–589`). A Terra challenger does not inherit that fallback. Check its actual account limits and failure behavior in the later challenger experiment; count missing/degraded challenges as failures, not savings. Do not generalize this legacy guard or add a new fallback without an observed need and review.

### Behavior and integrity findings

Every response parsed, covered its expected claims, and used existing evidence IDs. That does **not** establish correct claim mapping, direction, or reasoning. A post-run check with the repository's existing `isVerdictDirectionPlausible` found only **7/16 baseline**, **4/16 disabled-thinking**, and **10/16 medium-thinking** raw claim outputs structurally plausible. This check includes claim mapping, citation buckets and truth direction. These are uncorrected advocate outputs; the subsequent production debate/validation was not run. They are not complete-report failure rates or a new semantic quality score.

Per-family counts are German **5/8, 2/8, 6/8**; Portuguese **2/6, 2/6, 4/6**; hydrogen **0/2 for every arm** (baseline, disabled, medium). Hydrogen fails because each output cites items labelled `neutral` as directional contradiction, not because missing legacy applicability is automatically invalid. The Portuguese fairness pool contains no contradicting item mapped to AC_03: the baseline cites a sibling claim's item, the disabled arm assigns sub-50 truth to supporting-only citations, and medium's first repetition cites neutral items as support. Moving to 55 with a supporting-only list can pass this rule without establishing better reasoning. Keep these problematic fixtures visible; do not discard them to improve a denominator.

## 6. Balanced cost model

**Use the observed token ratios as the primary sensitivity.** The vendor's approximate 1.3× tokenizer average understates input inflation in every pilot fixture:

| --- | ---: | ---: | ---: |

| Portuguese input, per call | 19,320 | 27,850 | 1.442× |
| Hydrogen / English input, per call | 7,703 | 12,512 | 1.624× |
| Visible output, six disabled-thinking calls | 13,747 | 14,522 | 1.056× |

The disabled arm's input cost barely changed: **$0.247002 → $0.245528**. Output cost fell **$0.206205 → $0.145220**, accounting for **97.6%** of its $0.062459 saving. Medium and default-high thinking then added billed output. Lower token prices alone do not predict the cost of an analysis.

Applying the medium arm's +8.6% cost multiplier to the historical Sonnet share would increase recorded whole-job LLM cost by approximately **4.7%**, to **$1.0704/job**; applying the disabled arm's multiplier gives approximately **−7.5%**, to **$0.9463/job**. These are **advocate-derived extrapolations, not forecasts**: clustering, selection, reconciliation, retries and high-volume extraction did not participate. Historical clustering's output/input ratio was about 0.775 versus 0.167 in the baseline advocate screen, making the shared multiplier particularly weak there.

For comparison only, the eight-job historical slice also supports these idealized scenarios:

| Scenario | Estimated recorded LLM cost/job | Change |
| --- | ---: | ---: |
| Historical baseline | $1.0226 | — |
| Sonnet 5 at identical token counts, no extra thinking | $0.8380 | −18.0% |
| Sonnet 5 with assumed 1.3× input and output, no extra thinking; optimistic on observed input | $0.9487 | −7.2% |
| Captain's +25% envelope applied to that historical baseline | $1.2782 | +25.0% |

Formula: `other recorded LLM cost + Sonnet input × candidate input rate + Sonnet billed output × candidate output rate`. Retries, cache writes, changed output length, changed downstream call counts, and additional evidence change the answer.

Under the illustrative 1.3× scenario, approximately 32,944 **additional billed output tokens per job across all upgraded calls** would consume the remaining +25% envelope. That is a sensitivity calculation, not a suggested thinking budget. A model can be cheaper per token and more expensive per completed analysis.

For the later challenger comparison, repricing the recorded GPT-4.1 tokens at Terra's base rates increases this eight-job slice by only $0.0318 before thinking, caching and tokenization differences. The opportunity is better independent criticism at a small allocation share; saving the existing 2.25% share is not the primary reason to replace it. Preserve provider diversity and measure challenge validity, not challenge count.

Use **total provider/search cost per usable report**, plus median and tail latency, for the rollout decision. Also show per-attempt cost and failure rate so cheap incomplete analyses do not make the economics appear better.
