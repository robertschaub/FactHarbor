# Contributor processes

Contributions improve FactHarbor's system, documentation and evidence quality. Reporting a questionable result is useful: include the relevant sources and explain the problem, while keeping credentials, personal information and restricted evidence out of public issues.

## Propose and review a change

1. Start with the [contribution guide](https://github.com/robertschaub/FactHarbor/blob/main/CONTRIBUTING.md), current code and applicable repository instructions. Choose a bounded issue or documentation improvement.
2. Describe the observed problem, evidence, intended behavior and alternatives. Preserve existing decisions and open work; do not infer that a dated record is obsolete.
3. Implement the agreed scope and perform proportionate checks. Public setup and builds must remain self-contained. Analysis changes need appropriate quality and multilingual verification.
4. Seek maintainer review. Material architectural or policy changes need the relevant decision authority. Resolve findings with evidence and record meaningful limitations.
5. Publish or deploy only within explicit authorization. A proposal, local test or code review does not authorize a production change or paid evaluation.

## Analytical responsibilities

Preserve claim fidelity, evidence traceability, evidence-emergent boundaries and the distinction between truth and confidence. Investigate a general failure mechanism rather than manually adjusting a verdict to fit a preferred answer. Semantic decisions remain LLM-based and topic-neutral. Use only approved exact analysis inputs when working as a project agent; submitting live analyses needs separate authority.

## Participation and conduct

New contributors can start with a small issue, clarification or documentation correction. Review and maintenance responsibilities require an explicit assignment; contribution count does not automatically grant access or authority. Keep discussion constructive, explain objections and support claims with evidence. Harassment, discrimination and attempts to bypass safety or review rules are unacceptable.

Follow the [global rules](../globalrules/index.md), [governance](../../governance/index.md), [licensing](../../legal-and-compliance/open-source-model-and-licensing/index.md) and [contributor agreement](../../legal-and-compliance/cla/index.md). Contracted work, payments and formal association roles require their own arrangements.
